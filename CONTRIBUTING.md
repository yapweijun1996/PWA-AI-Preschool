# Contributing

1. Use a feature branch. Before editing, read `AGENTS.md`, `README.md`, and `docs/`.
2. Do not add real personal data, classroom audio/video, any credentials or company-specific branding.
3. Keep technical comments and code in English; use DOM-safe `textContent` for user content.
4. Create/regress unit tests for schema, source IDs and provider errors. Add browser tests for UI changes.
5. Run `npm run check && npm test` and record manual browser and Gateway checks.
6. No push/merge/deploy or production gateway setting changes without explicit owner authorization.
7. Any production feature proposal must explicitly list privacy, authorization, tenancy, retention and security acceptance tests.
